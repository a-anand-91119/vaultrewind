## Approval A: controller installation and private bootstrap

Before execution, the owner must approve the controller host, reviewed checkout/image, project name, durable paths, origin, network egress and proxy/TLS work. No source-host authorization is implied. Preserve the supplied [compose.yml](../compose.yml) and [Dockerfile](../Dockerfile) boundaries; do not introduce another storage service or proxy product as a required dependency. An existing suitable reverse proxy is preferred if the owner selects it; selecting a new one is an owner decision.

Set `OWNER_DATA_DIR`, `OWNER_PUBLIC_ORIGIN` and `OWNER_COMPOSE_PROJECT` privately to reviewed **nonsecret** values. The directory must be a dedicated absolute persistent location outside checkout/source data, with canonical non-symlink ancestors; choose values representable safely in `.env` (no newline or interpolation characters). The origin is `https://` plus the exact approved hostname and optional port, with no path/query/userinfo. Project name must remain stable so its PostgreSQL volume is reused.

```sh
sudo python3 scripts/prepare-install.py \
  --data-dir "${OWNER_DATA_DIR:?NEEDS OWNER INPUT}" \
  --origin "${OWNER_PUBLIC_ORIGIN:?NEEDS OWNER INPUT}"
```

The [installer](../scripts/prepare-install.py) creates private files without starting services. It does **not** overwrite existing secrets or an existing `.env`; review existing values deliberately rather than assuming rerunning changes them. It creates `.secrets` mode 0700; new `master_key` (32 random bytes), `bootstrap` and `database_password` files mode 0600; `.env` privately; and five data directories mode 0700. With root, the secret files and data subdirectories are owned by **10001:10001**. Run Compose as the installation administrator able to read the private `.env`, or arrange that file's owner-only access for the chosen operator. For non-root preparation an administrator must arrange service ownership before startup. Do not broaden permissions to solve startup failures; inspect existing files as well as newly created ones.

The actual persistence map is:

| Host location | Container location / purpose | Preservation requirement |
| --- | --- | --- |
| `.secrets/master_key`, `.secrets/bootstrap`, `.secrets/database_password` | `/run/secrets/master_key`, `/run/secrets/bootstrap`, `/run/secrets/database_password` | Protected file mounts, 0600, UID 10001 readable; keep independent secure copies of required keys/passwords outside controller backup repositories. Bootstrap is one-use, not a default password. |
| `$OWNER_DATA_DIR/backups` | `/var/lib/vaultrewind/backups` | Durable encrypted application/safety/controller repositories; owner-only 0700. |
| `$OWNER_DATA_DIR/staging` | `/var/lib/vaultrewind/staging` | Private plaintext work/retained recovery evidence; 0700; resolve failed work before cleanup. |
| `$OWNER_DATA_DIR/cache` | `/var/lib/vaultrewind/cache` | Restricted tool/image-related work; never confuse it with provider state. |
| `$OWNER_DATA_DIR/provider-credentials` | `/var/lib/vaultrewind/provider-credentials` | Durable encrypted pending rotations/session registry; **never TTL-clean** or discard on recreation. |
| `$OWNER_DATA_DIR/metadata` | Created, **not mounted by supplied Compose** | Not the PostgreSQL data store; do not advertise it as a database backup. |
| Compose logical volume `database` | DB `/var/lib/postgresql/data` | Preserve the selected project's actual named volume. Never use `down --volumes` or volume pruning. |

API, worker and migration roles share these application mounts and secret files. The controller runs as UID/GID 10001 with read-only root, all capabilities dropped, no-new-privileges and private `/tmp`. There is **no Docker socket mount**; restore testing uses a separately enrolled SSH runner. Keep PostgreSQL unexposed. The production API is bound only to **`127.0.0.1:8097`**, container port 8080.

After separate installation approval and confirmation that both `vaultrewind:0.1.0` and the exact pinned PostgreSQL image in Compose are present locally:

```sh
docker compose --project-name "${OWNER_COMPOSE_PROJECT:?NEEDS OWNER INPUT}" \
  -f compose.yml config --quiet
docker compose --project-name "${OWNER_COMPOSE_PROJECT:?NEEDS OWNER INPUT}" \
  -f compose.yml up --detach --no-build --pull never
```

This explicit startup refuses implicit image pulls/builds. Missing images are a stop condition, not permission to fetch. Compose orders DB health, `migrate` (`alembic upgrade head`), then API/worker. Inspect failures before retrying migrations. [Compose up](https://docs.docker.com/reference/cli/docker/compose/up/) defines these startup flags; [Compose config](https://docs.docker.com/reference/cli/docker/compose/config/) documents `--quiet`. Do not use `compose.dev.yml`, disable Secure cookies, expose port 8097 publicly or replace PostgreSQL with SQLite for production.

If initial controller acceptance fails before source enrollment, stop only the approved controller services and preserve its volume, keys, repositories and provider state for diagnosis. For a later upgrade, first preserve a verified metadata backup and previous image/configuration; review migration compatibility on a disposable copy. Do not run a destructive Alembic downgrade or replace a live database to undo a migration. Restore a known compatible controller/catalog pair only through the reviewed empty-database recovery workflow. Source/helper removal requires confirmation that no recovery journal is armed or uncertain.

### HTTPS, headers and roles

Route the approved HTTPS origin through the selected proxy to loopback port 8097. A containerized/remote proxy cannot use its own loopback to reach this binding; any reviewed networking override is separate installation work. Preserve Host and Origin, forward the external scheme through trusted proxy configuration, prevent direct access, and strip untrusted forwarded headers at ingress. Configure `VAULTREWIND_PUBLIC_ORIGIN` exactly; `VAULTREWIND_SECURE_COOKIES` defaults true. No broad CORS or insecure-cookie exception.

Preserve `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and the app CSP (`default-src 'self'; frame-ancestors 'none'`). Add reviewed transport security at the TLS proxy; enable HSTS only after confirming the hostname's HTTPS policy. Do not log bodies, cookies, authorization headers or OAuth callback queries. Avoid caching/buffering job progress; allow long reads if an SSE transport is introduced. **Current `/jobs/{id}/events` returns authenticated JSON polling with sequence IDs**, not an SSE-only contract. Verify reconnect/polling through the chosen proxy; no WebSocket dependency is needed.

Bootstrap privately using the mounted one-time secret and a unique administrator password/timezone. No public registration/default password. Confirm `vr_session` is Secure/HttpOnly/SameSite=Lax and browser mutations enforce matching Origin plus `vr_csrf` / `X-CSRF-Token`. Create viewers only as needed: they read sanitized status and cannot backup, restore, export keys, delete or change policy. Root/Docker administrators can inspect host files and process environments: repository/provider encryption does not protect against a compromised running controller. Do not expose process dumps, raw tool output or shell tracing. Secrets travel through private files/stdin or rebuilt subprocess environments, not argv.

4. **Accept first backup:** require complete inventory/SQLite/image evidence, exact committed manifest readback on every required copy, independently known source final state, full repository data read and full restored-byte verification. Then run the separately enrolled isolated application runner: private data copy, no production ports/routes/source mounts/outbound notifications/cloud credentials. Record structural/startup evidence separately from dedicated synthetic authenticated proof. 5. **Only then request alternate-rehearsal authorization:** owner approves exact snapshot/copy, compatible prepared alternate target, empty/existing state, paths/ports/URL overlays/dependencies, isolation, outage implications and cleanup. A replacement requires pinned local safety storage; no skip switch. Confirm a fresh short-lived plan bound to snapshot, target fingerprint/revision and creator. Leave the source, its schedule, DNS and proxy unchanged. This document performs no alternate or original production restore.

**Go/no-go:** proceed only when the immediately preceding stage has saved evidence and its own explicit approval. Missing required scoped recovery evidence, pending owner UI acceptance or an owner objection, identity/checksum mismatch, unsupported dependency, missing mount, unverified watchdog, unresolved journal/lease, provider-state failure, inadequate space or unaccepted long-term consent is a no-go for the affected next stage. The completed LOCAL synthetic proof supplies only its stated evidence; it grants no production permission. Record the blocker and retain recovery material; do not turn acceptance scopes into an all-cases claim.

**Before activation:** failed staging/image/candidate validation must leave or recover the original; verify original service state before recording `rolled_back`. Replacement cannot switch until its exact safety snapshot UUID, complete durable local copy/manifest readback and automatic pin are confirmed. Retain the old generation/container/deployment and journal for the approved grace. If safety durability fails, abort and recover the original; cloud upload is not a substitute while stopped.

**After activation may have happened:** preserve the new generation and possible client writes; reconcile the same operation and public endpoint/restart-policy evidence. Unresolved activation is `needs_attention`, never silent rollback. A later rollback requires a newly confirmed restore and its own safety capture. `rollback_failed` means preserve both generations/journal and escalate, not claim recovery.

**Emergency release decision:** owner/incident operator must confirm the exact host/instance/operation, activation boundary, current physical writer/generation, intended running/stopped state and the exact pinned safety snapshot ID/copy/readback before approving any manual recovery, lease release or removal of old generations. There is no general emergency force-release or skip-safety command in this runbook. Expired leases are not proof a process stopped. Keep fencing/journals and provider sessions until reconciliation; never kill the only watchdog, force-unlock a live repository or delete journals to admit new work. `SOURCE_RECOVERY_FAILED` takes priority over uploads. A physically down host requires owner infrastructure recovery and local-console responsibility.

The owner supplies a reachable incident operator, independent console access, verified host keys, key/kit custody, capacity, maintenance/client communication decisions and the explicit stop/restore approvals. Sign off separately on scheduling, retention/unpin/cleanup, long-term cloud consent and any DNS/proxy cutover. Close acceptance only with observed source/target state, protected recovery points, notification delivery state and unresolved limits recorded.
