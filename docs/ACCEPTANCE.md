## Upgrade and evidence rules

Helper/profile changes require reviewed checksums/protocol admission before source changes; armed or uncertain operations block upgrades. Historical reconciliation repairs only proven superseded metadata under the host lock, preserving warnings/history and leaving old public readiness unverified. Empty-target rebinding requires proven emptiness and identical physical roots; existing-application descriptor/root changes reject, and stale confirmations must be regenerated. See [operations](OPERATIONS.md), [historical migration](evidence/historical-migration.json), [activation tests](../tests/unit/test_activation_binding.py) and [browser attempts](evidence/browser-attempts.json).

[TESTING.md](TESTING.md) and [the evidence index](evidence/README.md) preserve detailed procedures, earlier failures and report limits. The specification's fault checklist is broader than the recorded runs; planned/running work is never a passing result.
